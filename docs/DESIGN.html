3资源池（Resource Pool）

文件 testkit/pool/resource_pool.py · 类 ResourcePool

需求实现要点
YAML 持久化每次 add/acquire/release 后立即原子写回（tmp + os.replace）
跨进程互斥FileLock(path + ".lock")，pytest-xdist 多 worker 共享同一把锁
预操作 reload加锁后 _read() 重新读盘，无内存缓存，杜绝陈旧状态
重试 + 批量分配acquire(count, predicate, retries, interval)，锁内按 count 批量标记
通用结构资源为通用 dict，仅约定 status 字段，id_field 可配置
CRITICAL status状态严格只有 "free" / "allocated"，_validate_status 拒绝其他取值
 
class ResourcePool:
    def __init__(self, path, retries=3, interval=1.0, id_field="id")
    def add(self, resource: dict)              # 新增 free 资源
    def acquire(self, count=1, predicate=None, retries=None, interval=None) -> list[dict]
    def release(self, resources)                # 归还为 free
    def release_all(self);  def remove(self, resource_id);  def list(self)

4异常层级（Exception Hierarchy）

文件 testkit/exceptions.py

TestKitError  # 框架基类：携带 original_exception 保留异常链 + context 字典
├── ConfigError        # 配置加载/校验
├── PoolError          # 资源池
├── HTTPError          # HTTP（含 status_code / response_data）
│   └── ResourceNotFoundError  # 404 自动转换（含 resource_type / resource_id）
├── SSHError           # SSH（含 command / exit_code / stderr）
├── FixtureError       # 并发 Fixture Guard
├── CleanupError       # 资源清理
└── PipelineError      # Pipeline 编排

关键机制：context 字典（异常 message 由 context 拼接生成，便于诊断）；404 → ResourceNotFoundError（携带 resource_type/resource_id）；链式保留（original_exception 不丢失完整 traceback）。

@dataclass
class SSHResult:
    command: str; stdout: str; stderr: str; exit_code: int; duration: float
    @property ok -> bool   # exit_code == 0

class SSHExecutor:
    def connect(self)                                 # 直连或经跳板机隧道
    def execute(self, command, timeout=None, raise_on_error=False) -> SSHResult
    def get_architecture(self, refresh=False) -> str    # uname -m，缓存
    def close(self)

7并发 Fixture Guard

文件 testkit/fixture/guard.py · 类 ConcurrentFixtureGuard

CRITICAL：6 个显式核心方法全部提供，其中 mark_failed() 与 wait_until_created(check_fn, timeout) 为硬性要求。
class ConcurrentFixtureGuard:
    def should_create(self, metadata=None) -> bool   # 首调用 True，其余 False
    def mark_created(self, metadata=None)            # 创建者构建完成后调用
    def mark_failed(self, metadata=None)             # 创建失败调用（REQUIRED）
    def is_creator(self) -> bool
    def wait_until_created(self, check_fn, timeout) -> bool
        # 非创建者轮询用户定义的 readiness 检查，非仅查 state 文件
        # 例如：lambda: api.get_cluster_status() == "Available"
    def cleanup(self) -> bool                          # 仅创建者删除 state 文件
    def exclusive(self)                              # 独占临界区（多进程串行）

另支持 超时接管：creating 状态超过阈值视为崩溃，允许接管重建。

13多阶段 Pipeline 编排

文件 testkit/pipeline/stage.py · 类 Pipeline / StageResult

需求实现要点
串行执行按序执行，任一失败后续 stage 跳过
resume_from 断点续跑从指定 stage 继续，跳过已完成 stage
skipped 标记跳过结果标 "skipped"，不影响最终成功判定
无状态不引入 checkpoint 文件，恢复点由用户指定
 
class StageResult:
    status: str  # "passed" | "failed" | "skipped"
    @property passed / failed / skipped -> bool

class Pipeline:
    def add_stage(self, name, fn) -> "Pipeline"
    def stage(self, name) -> Callable           # 装饰器形式
    def run(self, resume_from=None, context=None) -> list[StageResult]
    @property success -> bool

from testkit import ConfigRegistry

综合用例

def test_create_cluster(global_config):
    client = HTTPClient(global_config.api_base, auth=TokenAuth("${TOKEN}"))
    guard = ConcurrentFixtureGuard("/tmp/cluster_fixture.json")

    if guard.should_create():
        try:
            resp = client.post("/clusters", json={...})
            guard.mark_created(metadata={"id": resp.json()["id"]})
        except Exception:
            guard.mark_failed(); raise
    else:
        assert guard.wait_until_created(
            lambda: client.get("/clusters").json()["status"] == "Available",
            timeout=120,
        )
