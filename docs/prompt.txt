# Task
Design a generic Python automated testing framework for systems with "REST API management plane + SSH node plane".
Zero business coupling. Each module can be used independently.

# Architectural Principles (Core Constraints - Each Must Be Reflected)

## 1. Resource Pool
- YAML persistence: state changes are immediately written back to file
- FileLock for cross-process mutual exclusion (support pytest-xdist multi-worker)
- Pre-operation reload: acquire/release operations lock first then read latest state from file, no in-memory cache
- Support retries (retries + interval) and batch allocation
- Resource structure is generic dict, no predefined field names
- **CRITICAL:** Status values must be exactly "free" and "allocated" - no other values like "busy", "disabled", "available", or "in_use"

## 2. SSH Executor 
- Dual mode: direct connection + jump host (direct-tcpip tunnel)
- Jump host mode: open channel through existing SSH connection's transport, no intermediate shell
- Command execution returns structured result (stdout/stderr/exit_code/duration)
- Automatic log sanitization (passwords replaced with ***)
- Architecture detection support (uname -m, result cached)

## 3. HTTP Client
- Pluggable authentication strategy (Token/Cookie/ApiKey/Custom, unified interface)
- Dual-layer Token refresh: proactive expiration check before sending (buffer time configurable), passive refresh on 401 as fallback
- Real-time credential reading: re-fetch credentials from auth strategy before each request, no cached copy from initialization
- extra_headers: per-request header override/append, does not pollute Session
- Unified exception hierarchy (distinguish 404/network/timeout/status codes) 
- **CRITICAL:** Must provide `_request_with_files(method, path, file=None, data=None, extra_headers=None, base_url_override=None)` method for multipart/form-data uploads and custom base_url. Automatically strips Content-Type header (let request set multipart boundary). Support base_url_override for calling external services.

## 4. Concurrent Fixture Guard
- State file (JSON) + FileLock for cross-process coordination
- First worker creates, other workers wait and reuse
- Timeout takeover: creating state exceeding threshold is treated as crash, allows takeover
- Only creator is responsible for cleanup
- Support exclusive lock sections (multi-process serial execution of critical sections)
- **CRITICAL:** Must provide these explicit core methods:
  - `should_create(metadata={}) -> bool`: first caller returns True, others return False
  - `mark_created(metadata={})`: creator calls after resource is built
  - **`mark_failed(metadata={})`**: creator calls if creation fails (REQUIRED)
  - `is_creator() -> bool`: return whether this process is the creator
  - **`wait_until_created(check_fn: Callable, timeout: float) -> bool`**: non-creators poll user-defined readiness check (REQUIRED). check_fn is NOT just checking the state file - it's a callable like `lambda: api.get_cluster_status() == "Available"`
  - `cleanup()`: removes state file

## 5. Test Resource Cleanup
- LIFO stack: later-registered resources are cleaned up first (preserves dependency order)
- Async resources support pre-cleanup waiting (e.g., wait for cluster deletion to complete)
- Cleanup failure triggers automatic retry (retry_count + retry_interval)
- Cleanup failure does not block subsequent resource recovery
- skip_cleanup_on_failure: skip cleanup when test fails, preserve state for debugging

## 6. Configuration Loading
- YAML multi-environment merge (default + envs.(env) deep merge)
- ${VAR} placeholder substitution with environment variable values
- .env file loading injects into os.environ (existing environment variables take precedence)
- Pydantic model validation (type safety + defaults + required field checks)
- **CRITICAL:** Must provide a Configuration Registry pattern:
  ```python
    class ConfigRegistry:
      def register(self, yaml_path: list[str], model_cls: type[BaseModel], fixture_name: str = None):
        """Register a YAML path -> Pydantic model mapping.
        yaml_path: e.g., ["common"] loads common section from dynamic.yaml
        model_cls: Pydantic model to validate the section
        fixture_name: optional pytest fixture name to bind the loaded config
        """
  ```
  Usage in conftest.py:
  ```python
  REGISTRY = ConfigRegistry("config.yaml")
  REGISTRY.register(["common"], CommonConfig, fixture_name="global_config")
  REGISTRY.register(["ssh"], SshConfig, fixture_name="ssh_config")

  @pytest.fixture(scope="session")
  def global_config() -> CommonConfig:
    return REGISTRY.get("global_config")

  ```

## 7. Async Polling Utility (WaitHelper)
- Generic until() method: polls condition function until it returns expected value or timeout
- Exception tolerance: condition exceptions do not interrupt polling, continue waiting
- Proactive Token refresh during long polling: prevents Token expiration during polling
- Readiness judgment is defined by caller (framework does not preset business state machines)

## 8. Exception Hierarchy
- Framework base class -> module exceptions (HTTP/SSH/Pool/Config/Fixture)
- Exceptions carry context: domain information like status_code/response_data/resource_id automatically appended to message
- Base class carries original_exception to preserve exception chain
- 404 automatically converted to ResourceNotFoundError (with resource_type + resource_id)

## 9. Log Verbosity
- Inspired by k8s --v=N pattern, log_verbosity is the single control point
- Custom levels: V2 (API summary), V4 (full response body), V5 (trace-level)
- pytest handler level set to NOTSET (0), no secondary filtering, otherwise custom levels below DEBUG would be discarded
- Automatic sensitive data sanitization (passwords/Tokens/keys replaced with ***)

## 10. Data Model Layer
- Builder pattern: chainable construction of complex request bodies (with_xxx returns self), build() outputs standard dict
- from_api_response pattern: automatic mapping from API response dict to object attributes + convenience properties (e.g., id = metadata.uid)
- Model does not hold Client references (Client-Model separation)
- Exceptions are not swallowed: type errors in from_api_response are raised normally, not silently reset

## 11. Multi-stage Pipeline Orchestration
- Serial stage execution: stages execute in order, any failure causes subsequent stages to skip
- Resume from checkpoint (resume_from): continue from specified stage, skip completed stages
- Skipped stage result marked as "skipped", do not affect final success judgment
- Stateless design: no checkpoint files introduced, user manually specifies recovery point

## 12. General Constraints
- Zero business coupling: no preset business concepts like "node/cluster/organization"
- Complete type annotations, complete docstrings

# Tech Stack
pytest, pytest-xdist, requests, paramiko, pydantic, PyYAML, filelock, kubernetes

## 14. Pytest Plugin (CRITICAL Constraints)

The plugin must auto-register via the `pytest11` entry point. Every constraint below is non-negotiable:

- **CRITICAL:** Entry point group name must be `pytest11` exactly.
- **CRITICAL:** All registered CLI options must use the `--testkit-` prefix to avoid user namespace collisions (e.g. `--testkit-verbosity`, `--testkit-resume-from`, `--testkit-skip-cleanup-on-failure`, `--testkit-env`)
- **CRITICAL:** All auto-registered session/function fixtures must use the `testkit_` prefix (e.g. `testkit_cleanup`, `testkit_wait_helper`, `testkit_fixture_guard`).
- **CRITICAL:** Test failure detection must be automatic - implement `pytest_runtest_makereport` with `hookwrapper=True` and `yield` pattern to mark test failure on the item, so `ResourceCleanup.skip_cleanup_on_failure` works without any user code. Users must NOT need to wire failure detection themselves.
- **CRITICAL:** All custom markers must be declared in `[tool.pytest.ini_options].markers` to suppress `PytestUnknownMark` warnings.

## 15. CI & Release (CRITICAL Constraints)

- **CRITICAL:** PyPI publishing must use **Trusted Publisher (OIDC)**, not username/password or static tokens. The publish workflow requires `permissions: id-token: write`.
- **CRITICAL:** CI must run a matrix across Python > 3.10 on linux + windows + macOS
- **CRITICAL:** Coverage gate at 85% minimum ( `fail_under = 85`).

# Extended Capabilities

> Sections 19–28 continue the framework with direct Kubernetes cluster access, richer SSH file transfer and connection handling, generic parallel execution, and production-grade runtime controls.

---

## 19. Kubernetes Direct Client

A thin wrapper over the official `kubernetes` client library for direct cluster access via kubeconfig (complementary to the HTTP management-plane client).

- **CRITICAL:** Depends on `kubernetes` (add to dependencies). Not to be confused with the HTTP `Client` - this talks directly to the cluster API server.
- `from_kubeconfig(kubeconfig_dict)` classmethod for auth; `close()` to release the API client.
- CRUD helpers for core resources (apps/core/networking groups): Deployment / StatefulSet / DaemonSet / Pod /Ingress / ConfigMap / Secret / Namespace - each with list/get/create/delete where applicable.
- `exec_in_pod(namespace, pod_name, command, timeout)` using `kubernetes.stream.stream`.
- Errors wrapper in the framework exception hierarchy.

---

## 20. SSH Enhancements (transfer / reconnect / verify / find)

Extend the SSH executor beyond plain command execution with the file and connection capabilities a real SSH test flow requires.

- **File transfer (SFTP):** `scp_via_jump` - stream file from the current host to a target reachable only through the current SSH connection (chunked read/write, 64 KiB chunks, never load the whole file into memory)
- **Double-hop transfer:** `scp_via_double_jump(source_ssh, local_path, target_ip, remote_path, ...)` - read from a *source* SSH host, forward to a target through the current connection (the first server(public ip) -> the second server(private ip) -> the third server(private ip) scenario).
- **File search:** `find_package(pattern)` - glob match a remote path via SFTP `listdir` + `fnmatch`, return first match.
- **File existence:** `file_exist(remote_path)` -> bool (via `ls` command).
- **Connection verification:** `verify()` - execute a sentinel echo and assert the expected token appears (used as the standard connectivity gate after every (re)connect in multi-stage flows).
- **Auto-reconnect:** detect inactive transport; reconnect once automatically and retry the failed command. Applies to both `execute` and file operations.
- **Keepalive:** `transport.set_keepalive(60)` on every connection to survive long-running operations.
- **Host key policy:** configurable `reject` / `warn` / `auto` (AutoAddPolicy), not hard-coded.
- **Raw client access:** `raw` property exposing the underlying `paramiko.SSHClient` for advanced operations.

---

## 21. Parallel Execution Utility

A generic ordered-parallel map for executing independent tasks and collecting result/errors.

- `parallel_map(func, items, max_workers=5, timeout=None, on_error="collect", desc="tasks", error_handler=None) -> list`
- **Preserve order:** result list follows `items` order; skipped/failed tasks are omitted (caller decides how to interpret missing slots).
- `on_error="collect"` - per-task exceptions are logged (or converted via `error_handler(item, exc)`); execution continues. `on_error="raise"` - first exception aborts the batch.
- Based on `concurrent.futures.ThreadPoolExecutor`.

---

## 22. Kubernetes Resource Quantity Utility

- `to_mib(value) -> int`: normalize K8s quantity string (`2048Mi`, `2Gi`, `1024Ki`, raw bytes) to integer MiB. Returns 0 for `None`.

---

## 23. Logging Enhancements

Extend the existing verbosity-based logging with production runtime controls.

- **Rotating file handler:** optional `RotatingFileHandler` (configurable `maxBytes`, default 10 MiB, and `backupCount`, default 5). The pytest handler stays NOTSET as before.
- **paramiko suppression:** `paramiko` protocol logs default to WARNING and are only surfaced at maximum verbosity (v5) to avoid log flooding.
- **Runtime adjustment API** (class-level, framework logger):
  - `set_level(level_str)`
  - `set_verbosity(v)` - map 0-5 to the existing `--v=N` scheme
  - `add_file_handler(filename)` / `remove_file_handler(filename)` - idempotent
  - `get_logging_info()` - snapshot dict of current level/handlers
- Sensitive-data sanitization applied to all handlers.

---

## 24. Config Template Generation

Generate a `dynamic.yaml`-style template from the registered Pydantic models (reverse of validation).

- **From registered models:** walk each `ConfigRegistry` registration, render every model field into a template dict:
  - default / `default_factory` values used as-is
  - otherwise a placeholder by type (`<string>`, `<int>`, `<float>`, `<bool>`); nested `BaseModel` fields recurse.
- **Filter by used fixtures:** when a set of used pytest fixture names is provided, include only sections whose registered `fixture_name` intersects the set; sections with no fixture name are always included (global config)
- `dump_template(path)` - write the merged template as YAML.

---

## 25. ResourceCleanup State Queries (minimal)

Two small state-query helpers on the cleanup context (already has `register` / `cleanup` / `__len__`).

- `remove(resource_id) -> None` - drop a registered cleanup entry so a test that cleaned up inline does not double-clean. Generic: matches the entry by the user-supplied `name` used at `register`.
- `pending_count -> int` - number of entries still to be cleaned (alias of `__len__`).

---

## 26. AuthStrategy Lazy Token

Make `TokenAuth` constructible before credentials exist (no network IO at construction), so fixtures can build clients while the environment is still being provisioned.

- `TokenAuth(access_token: str | None = None, ...)` - token may be `None` at construction.
- **CRITICAL:** The token is fetched on the *first* `get_headers()` call (via the `token_provider` when `access_token` is `None`), never at `__init__`.
- `is_expired()` / proactive refresh-buffer check and the existing `should_refresh_on_401(response)` hook are unchanged.
- 400-with-"token is expired" detection is intentionally NOT built in: that error text is backend-specific, and the existing `should_refresh_on_401(response)` override point already lets users extend refresh triggers to 400 responses.

---

## 27. wait_until_deleted Convenience

A small generic helper on the polling utility, proven by three business usages (`cluster_deleted` / `addon_deleted` - all "poll existence until absent").

- `wait_until_deleted(check_exists, timeout=None) -> bool` - poll `check_exists` (callable returning whether the resource still exists); a raised `ResourceNotFoundError` (or equivalent 404 signal) count as "deleted". Built on the existing `until()` with its exception tolerance.
- All other readiness logic stays caller-defined (no business state machines in the framework).
